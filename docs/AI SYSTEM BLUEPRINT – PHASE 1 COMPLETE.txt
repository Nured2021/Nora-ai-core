4. HOW USER OPERATES (PILOT MODE)
User writes one input. NORA understands:
Input Type Example What NORA Does
Build command "build a todo app" Starts building. Shows every step.
Pilot command "/deploy to production" Deploys immediately
Question "what is the status of job #42?" Shows live status
Input Type Example What NORA Does
Correction "change the button to red" Updates running job
Chat "can you add search?" Adds feature while job runs
NO STOPPING – User sends next command while previous job still running. Both work.
5. NO-STOP QUEUE
Jobs run forever until user cancels. Queue system:
- Redis + Celery backend
- Jobs survive browser close
- Jobs survive API restart (persistent queue)
- User can cancel with /stop <job_id>
- Multiple jobs run in parallel
6. LIVE STREAMING
WebSocket-based live log streaming:
- Every job step broadcasts via WebSocket
- Dashboard subscribes per job or global feed
- Logs stored in DB for replay
- Real-time status updates
7. HUMANLOOP APPROVAL SYSTEM
Critical actions require approval:
- /deploy → requires ADMIN or DEVELOPER approval
- Destructive operations → requires approval
- Approval UI shows: action details, YES/NO/MODIFY buttons
- Approval state stored in DB
- Timeout → auto-reject (configurable)
8. MULTI-USER ROLES
Role Permissions
ADMIN Full access, approve deployments, manage users
DEVELOPER Build, deploy with approval, view all jobs
VIEWER Read-only, view jobs and logs
JWT-based authentication. Role-based route guards.
9. BRAIN CONNECT (PHASE 1 IMPLEMENTATION)
Layers 1-10 active in Phase 1:
1. Command History Memory – stores all commands per user
2. Code Pattern Recognition – tags generated code patterns
3. User Preference Learning – tracks user build preferences
4. System State Tracking – tracks all job/system states
5. HumanLoop Feedback Storage – stores all approvals/rejections
6. Deployment Target Memory – remembers deploy targets
7. Error Recovery Tactics – logs errors + recovery actions
8. Multi-User Role Mapping – maps users to roles/workspaces
9. Builder Template Library – stores reusable build templates
10. Real-Time Feedback Loop – live status feedback to user
10. TACTICS LIBRARY
Reusable build tactics stored and replayed:
- User can save a tactic (sequence of commands)
- Tactic has name, description, steps
- Tactic can be run with /tactic <name>
- Tactics visible in sidebar under TACTICS LIB
11. SYSTEM BUILDER (NORA-BUILDER)
Builds apps by natural language:
- User types: "build a todo app with React frontend"
- NORA generates: file tree, code stubs, config files
- Output visible live in dashboard
- Files stored in DB (Phase 1: mock output)
